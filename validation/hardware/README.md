ユーザーから「画面の表示ではうまくいっています」との報告と、CoreS3のログを受領しました。
この記録は、その提示区間を集計したものです。

| 項目 | 結果 |
|---|---:|
| CoreS3版 | 1.3.0-range |
| 基板間UART | 38400 bps、8N1 |
| ログ行数 | RANGE_STAT・RANGE_DATA 各33行 |
| 先頭から末尾の経過時間 | 32秒 |
| UART正常受信の増分 | 160回（5回/秒） |
| 19–21の測距成功の増分 | 160回 |
| 19–22の測距成功の増分 | 160回 |
| UARTエラー・欠落・重複・再起動カウンタ | 全行0 |
| 測距失敗累計r_bad | 62 → 62（増分0） |
| valid | 全行7（2距離と19番加速度が有効） |
| セッション | 全行2/2、reason=00/00 |
| tx_frame_ms | 80または90 ms |
| irq_us | 全行235 µs |
| tx_overruns | 全行0 |

この区間では、2系統の測距を継続しながらUARTで実測値を送信できています。
UART停止版との比較や距離精度を評価した記録ではありません。
`irq_us`は送信側ソフトウェアの計測値、`max_gap_ms`は受信アプリの処理間隔です。
オシロスコープで測定した波形・遅延を示すものではありません。

集計を再確認するには、リポジトリのルートで次を実行します。

```sh
python scripts/verify_hardware_log.py
```

CIでのこのチェックは保存ログと集計の整合性確認です。新しい実機試験を実行するものではありません。
