# Type2DK → CoreS3 UART送信試験 v1

2DKのPIO13（今までのSDA）から、CoreS3のGPIO2へ38400 bps / 8N1で送信します。
**これは通信確認用です。20バイトの試験データを50回/秒で送信し、距離測定・UWB・BLEは実行しません。**
CoreS3は1.2.0-uart、2DKは2dk_uart_tx_v1.binをセットで使用します。

## 1. 配線を外して両方を書き換える

電源を切り、2DKとCoreS3の間の信号線をいったん外します。
I2C用に追加したSDA・SCLの2 kΩ抵抗と、その電源線を外してください。
基板の4組の電源ジャンパは、そのままにします。

1. [UART用書き込みページ](https://temesotejam.github.io/type2dk-uwb-uart/uart.html)からCoreS3を書き込み、画面の `1.2.0-uart` を確認します。
2. 同じページから `2dk_uart_tx_v1.bin` をダウンロードします。
3. 2DKのシリアルモニターを閉じ、DK6Programmerのフォルダで次を実行します。

```powershell
.\DK6Programmer.exe -V 0 -P 1000000 -s COM19 -Y -v -p .\2dk_uart_tx_v1.bin
```

COM19はこれまで使っていた番号です。変わっていれば現在の番号に変更します。
`-v` は書き込み後の照合用です。書き込みと照合の完了を確認します。
現在のアプリを書き換えます。以前のUART0経由のUSB書き込み・ログ端子は維持します。

## 2. 電源を切って2本だけつなぐ

Type2DK EVK Rev.4.1のTP8を使用します。TP14とは別です。

| Type2DK | CoreS3 PORT A | 用途 |
|---|---|---|
| TP8の2番：PIO13 / SWDIO | 黄：GPIO2 | 2DK TX → CoreS3 RX |
| TP8の3・5・9番のいずれか：GND | 黒：GND | 共通GND |
| TP8の4番：PIO12 / SWCLK | 白：GPIO1 | 接続不要 |
| 接続しない | 赤：5 V | 接続不要 |

実物の1番表示と回路図で端子番号を確認してください。SWD書き込み器は外します。
両方をそれぞれUSB給電します。UART出力は2DK側I/O電源に従い、今回の実測は約3.0 Vです。
外付け抵抗もTP18への追加配線も不要です。CoreS3側のGPIO1/2の内蔵プルアップは無効です。
同じ線へI2Cセンサはつなぎません。2DK側はプッシュプル出力になるため、古いI2C版CoreS3と組み合わせないでください。

## 3. 受信を確認

2DKを起動すると約2秒後に送信を始めます。CoreS3は自動受信します。
`RECEIVING` が出たらCLEARを押し、30秒ほど確認します。

| 表示 | 期待する状態 |
|---|---|
| OK | 毎秒およそ50増加、30秒でおよそ1500 |
| RATE | およそ50/s。画面更新等による集計の揺れあり |
| BAD | 0（同期ヘッダを認識したフレームのCRC/形式不正） |
| MISS | 0（連番から推定した欠落フレーム数） |
| DUP | 0（同じ連番の重複） |
| RESET | 通常0。送信側リセットを検出すると増加 |
| FRAME_ERR / OVERFLOW | 0 |

`WAITING` はまだ正常フレームなし、`NO DATA` は最後の正常受信から500 ms超です。
CoreS3のUSBシリアルは115200 bpsです。毎秒の `UART_STAT` を5～10行送ると判定できます。
USBで `c` を送ってもCLEARできます。
`discarded` は同期前やデータ化け時に捨てたバイト数なので、途中接続直後は非ゼロになり得ます。
`max_gap_ms` はアプリで正常フレームを処理した間隔で、線上の厳密な到着間隔ではありません。

2DK側のUSBログも115200 bps / 8N1 / フロー制御なしです。
SW1で再起動すると `BOOT,2DK_UART_TX_V1`、続いて `UART_TX` が毎秒出ます。
**基板間の38400 bpsとUSBログの115200 bpsは別です。**

## 実装と検証範囲

- QN9090のPIO13をFUNC0のGPIO・プッシュプルへ設定。PIO12は入力・プルなし。
- 32 MHz FROとSysTickの経過クロックでビット周期を生成。1ビット833クロック（公称38,415 bps、設定38,400 bpsに対して+0.04%）。実際の精度にはFRO誤差も含みます。
- 8N1、LSB first。各バイト中は割り込みをマスク。タイムスタンプはフレーム作成時点。
- 20バイト/20 ms。同期4バイト、版/試験フラグ、32ビット連番、32ビット起動時刻ms、固定パターン、CRC16-CCITT-FALSE。
- CoreS3はハードウェアUART1で受信。タッチ等の内部I2Cは維持。
- ホストで既知CRCベクトル、全位置の1バイト破損/挿入/欠落、途中接続・再同期、連番と時刻の周回、送信側リセットを検証。
- 2DK BINのベクタチェックサム・ROMヘッダCRC・イメージ長・SHA256を検証。
- **38400 bpsの実機受信を確認済みです。UART波形・電圧余裕の外部測定は未実施です。**
- 測距併用版の動作確認は[実機確認記録](../validation/hardware/README.md)を参照してください。

再ビルド（ユーザー所有のSR040 SDKが必要。SDK自体は配布しません）：

```text
python type2dk/build.py --zig /path/to/zig --sdk-root /path/to/uwbiot-top --uart
pio run -e cores3_uart
```

測距併用版に戻す場合は、[測距版の手順](ranging/README.md)に従って対応する両機器のファームウェアを使用してください。
